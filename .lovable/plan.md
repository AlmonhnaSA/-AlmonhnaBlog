# خطة موحّدة لإدارة الصور والملفات بأمان

## النطاق وحدود الموافقة
- هذه خطة مبنية على فحص الكود ومجلدي ترحيلات البيانات، وليست نتيجة فحص ملفات الإنتاج.
- Lovable Cloud بيئة التطوير القديمة؛ بيانات وتخزين الموقع المباشر في المشروع المستقل، والاستضافة على Vercel، والصوتيات على R2.
- لم يُعدّل كود التطبيق أو بياناته أو إعداداته ولم تُحذف أو تُرفع ملفات أثناء الفحص. لا يوجد وصول إداري مباشر مؤكّد للمشروع المستقل هنا؛ لا أقدّم أعدادًا أو مساحة توفير تخصه دون فحصه فعليًا.
- الموافقة لتجهيز الكود والاختبارات فقط، لا لنشر الدوال أو Vercel أو تعديل/حذف بيانات الإنتاج؛ هذه تحتاج إذنًا منفصلًا.
- تبقى التصاميم والصلاحيات؛ لا تغيير للصوتيات أو Worker أو DNS أو كاش R2.

## نتائج الفحص الفعلي
| الموضع | الرفع الحالي | الاستبدال والحذف الحاليان |
|---|---|---|
| أغلفة المقالات وخدماتنا، صور الأعمدة والمتجر، صور المستخدمين، صور الخطوط الزمنية وأغلفة الحلقات | `ImageUpload`: رفع فوري إلى `images`؛ ضغط WebP بجودة 0.85 وحد أقصى 1920px عندما ينتج ملفًا أصغر | الرابط يتغيّر في المسودة ثم يُحفظ لاحقًا؛ الملف السابق والرفع المتروك يبقيان |
| صور معارض خدماتنا | `GalleryUpload`: الضغط نفسه؛ حتى 20 صورة؛ حد 5 MiB قبل الضغط | الإزالة تعدّل قائمة الروابط فقط؛ فشل دفعة جزئي قد يترك ملفات بلا روابط |
| PDF المعرض وصفحاته | الأصل يُرفع ثم تُحوّل الصفحات إلى JPEG بجودة 0.85 ومقياس 1.6؛ لا تمر بالمحسّن الموحّد | الأصل والصفحات قد تبقى عند فشل التحويل أو الحفظ؛ إزالة PDF تمسح الرابط فقط |
| صور المحرر واللصق | `rich-text-editor`: صور base64 داخل HTML، دون رفع Storage أو ضغط موحّد | حذفها ثم حفظ النص يزيلها من النص؛ لا ملف Storage مستقل لهذه الصور، وقد توجد أيضًا صور مدرجة بروابط |
| مرفقات المتجر | رفع مباشر إلى `store-files` باسم UUID؛ لا حد حجم/نوع محلي معلن في هذا المسار | الإزالة من المسودة أو حذف المنتج لا يحذف الملف الفعلي |
| الشعارات والصور الثابتة وبطاقات الاقتباس | أصول المشروع وروابط الأصول؛ لا رافع شعار وقت التشغيل؛ تصدير الاقتباس تنزيل محلي | لا تدخل في تنظيف Storage تلقائيًا؛ تُفحص كمراجع محتملة |

**قبل التنظيف:** حفظ المتجر والخطوط وإضافات المقالات متعدد الطلبات وبعض أخطائه غير مفحوص. غياب الخطأ لا يثبت التأثير على صف؛ يلزم حفظ ذري وقراءة النتيجة. الروابط والنصوص تسمح بمشاركة الصور، وملكية مجلدها لا تثبت انفراد استخدامها. سياسات الحذف المباشر القديمة وإعدادات المشروع المستقل تحتاج تحققًا مستقلًا.

## التنفيذ المقترح
### 1. الفحص والمعاينة أولًا
- تجهيز سكربت محلي **Read-only فعليًا**: لا يتضمن أو يستدعي upload/update/remove/delete أو تغيير إعدادات.
- يقرأ إعداد الاتصال من متغيرات محلية خارج الواجهة والمحادثة، ويتحقق من تطابق المشروع المقصود؛ لا يطبع المفاتيح أو رموز الروابط الموقّعة.
- يسرد جميع buckets والملفات مع pagination، ويقرأ جميع جداول التطبيق وأعمدة النص/JSON/المصفوفات بكل الحالات: المنشور والمعلّق والمرفوض والخاص. لا يعتمد على رؤية المستخدم المحدودة بالصلاحيات.
- يفحص الكود والأصول الثابتة ومؤشرات الأصول وروابط HTML وCSS وsrcset والروابط العامة والمحسّنة والموقّعة وترميز HTML وpercent-encoding المحدود؛ يطابق هوية **المشروع + bucket + مسار الملف** وليس اسم الملف وحده.
- يتعرّف على base64 ويبلغ حجمها التقريبي منفصلًا؛ ليست ملفًا قابلًا للحذف من Storage. يفحص مراجع الصوت للحماية، ويستثني ملفات الصوت ومجلداتها من التنظيف، ولا يتصل بـR2.
- قائمة حماية للمراجع الخارجية والثابتة؛ غياب استخدام خارجي لا يمكن إثباته من قاعدة البيانات وحدها.
- ينتج JSON وCSV وتقريرًا مختصرًا: الحجم، المراجع ومواقعها، التصنيف والسبب والثقة، وقت الفحص، المشروع، نطاق التغطية والأخطاء.
- التصنيفات: مستخدم مؤكّد، مرجع محتمل/ملتبس، محمي/خارج النطاق، مرشح غير مستخدم. أي جدول/صفحة غير مقروءة يجعل التقرير غير مكتمل ويمنع توصية الحذف.
- تُعرض المساحة الإجمالية ومساحة المرشحين **كتقدير محتمل لا كمساحة آمنة مضمونة**؛ الأرقام السابقة لبيئة التطوير لا تُعاد نسبتها للإنتاج.

### 2. توحيد تحسين الرفع دون إضعاف الجودة
- خدمة مشتركة لجميع الصور، بما فيها الصور الجديدة داخل المحرر وصفحات PDF والصور الشخصية.
- عدم تكبير الصور الصغيرة، الحفاظ على النسبة والشفافية، اختيار إعدادات مناسبة للصورة أو التصميم ذي النص، وإرجاع الأصل عند فشل التحسين أو عدم جدواه.
- إبقاء GIF المتحرك وSVG دون تحويل يفقد خصائصهما، مع التحقق من النوع وعدم معاملتهما كصور نقطية عادية.
- الحفاظ على جودة الصور الحالية أساسًا، وعدم إعادة ضغط الملفات القديمة أو تحويلها جماعيًا. ملفات المتجر المخصّصة للتنزيل تبقى كما هي حتى لو كانت صورًا أصلية مطلوبة.
- تحويل الصور **الجديدة** في المحرر إلى رفع موثّق ورابط بدل base64؛ المحتوى القديم يبقى دون إعادة كتابة.
- الحفاظ على تحسين العرض واختيار الحجم حسب العرض وDPR والرجوع للأصل. الضغط عند العرض لا يقلل حجم الأصل المخزّن.

### 3. حفظ موثوق وسجل مراجع
- تسجيل الرفع الجديد بهوية غير قابلة لإعادة الاستخدام، مالكه، حجمه، ونوعه، وربطه بجلسة مسودة مؤقتة.
- رفع الصورة الجديدة باسم فريد دون استبدال الملف القديم، والتحقق من اكتمال الرفع قبل السماح بالحفظ.
- حفظ كل عملية منطقية بمعاملة واحدة: العنصر والجداول التابعة ومراجع الملفات وقائمة المرشحين للتنظيف؛ منع الحفظ الجزئي وفحص الصف المتأثر وإصدار التعديل لمنع الكتابة المتزامنة الصامتة.
- التقاط مراجع العناصر التابعة قبل حذفها المتسلسل، خصوصًا منتجات المتجر والخطوط الزمنية وحذف محتوى الكاتب؛ لا تغيير معنى حذف الحساب أو صلاحياته ضمن هذه المهمة.
- تسجيل المراجع عبر حراسة معاملات تشمل الكتابات المباشرة أيضًا، حتى لا تتجاوز نسخة قديمة من الموقع سجل المراجع.
- تشمل المراجع جميع الحقول، ومنها أغلفة الحلقات و`timeline_stops.image_url` حتى دون رافع حالي لهذه الصور؛ لا تشغيل للحذف إن ظهرت بنية أو مراجع لا يفهمها الفاحص.

### 4. تنظيف آمن بعد نجاح الحفظ
- دالة خادم تتحقق من الجلسة ودور الإدارة أو ملكية المحتوى حسب العملية، لا من ادعاء المتصفح؛ التنظيف الجماعي للإدارة فقط.
- لا تقبل رابطًا عشوائيًا باعتباره تصريح حذف؛ تعتمد عملية موثّقة وسجل الملفات والمراجع. تمنع المضيف الخارجي والمسار الملتبس وملفات الصوت.
- بعد تأكيد المعاملة وقراءة المرجع الجديد، يفحص الخادم استخدام القديم في جميع المحتوى وفي قائمة الحماية والجلسات النشطة.
- **الفحص ثم الحذف وحدهما لا يكفيان:** قفل وحالة مشتركة بين إضافة المرجع والتنظيف تمنع إعادة ربط الملف أثناء حذفه؛ إذا تعذرت هذه الحماية يبقى الملف ولا يُحذف تلقائيًا.
- حذف الملفات عبر Storage API فقط، لا حذف صفوف `storage.objects` يدويًا.
- طابور موثّق قابل لإعادة المحاولة، مع سجل للفاعل والعملية والملف والحجم والسبب ونتيجة التحقق والحذف. فشل التنظيف يُعرض منفصلًا ولا يحوّل حفظًا ناجحًا إلى فشل أو يحذف الأصل عند فشل الحفظ.
- الرفع الملغى يُنظّف فقط إذا انتهت جلسة المسودة وثبت عدم الارتباط؛ مغادرة الصفحة ليست ضمانًا كافيًا، ويضاف فحص دوري محافظ للمسودات المتروكة.
- يبدأ النظام بـDry Run. الملفات القديمة غير المسجّلة تبقى مرشحات مراجعة ونسخ احتياطي وموافقة محددة؛ لا تنظيف تلقائي اعتمادًا على غياب رابط.

## الاختبارات والتحقق
- استبدال كبير بصغير: حفظ وقراءة الجديد ثم تأكيد غياب القديم غير المشترك عبر Storage API وقياس فرق البايتات، لا الاكتفاء بمسح الرابط أو صورة من الكاش.
- فشل الرفع أو الحفظ أو الصفوف التابعة أو التحقق: القديم يبقى، ولا رسالة نجاح مضلّلة.
- صورة مشتركة بين غلاف ونص/معرض أو عناصر مختلفة: لا حذف مع أي مرجع، حتى في المحتوى غير المنشور.
- حذف مقال/خدمة/منتج/خط أو محتوى كاتب: تنظيف غير المشترك فقط بعد نجاح المعاملة.
- إعادة ربط أثناء التنظيف ونسخة قديمة تكتب مباشرة وتكرار الطلب وانقطاع الشبكة: لا فقد ملفات مستخدمة.
- رفض تزوير الصلاحيات والمالك والمشروع والمسارات الملتبسة والروابط الخارجية؛ لا أسرار بالواجهة أو السجلات.
- روابط أصلية ومحسّنة وموقّعة ومشفّرة وHTML/JSON/srcset وpagination؛ القراءة الناقصة تمنع الحذف.
- Dry Run بلا كتابة؛ استثناء الصوت وR2 في كل مسار.
- صور شفافة وصغيرة وتصاميم نصية وGIF وSVG وPDF وفشل ضغط؛ اختبارات قواعد ومراجعة بصرية للجودة.
- اختبار كامل بحساب مخوّل وملفات جديدة في بيئة معزولة؛ تأكيد النتيجة عبر الواجهة وStorage، دون تجربة حذف ملفات قديمة.

## ما يُنفذ لاحقًا على المشروع المستقل
1. تشغيل جرد Read-only محلي والتحقق من المخطط والسياسات الفعلية، بما فيها ترحيلات `supabase/migrations` و`drizzle/migrations`؛ لا إعادة تشغيل الترحيلات القديمة عميانيًا.
2. مراجعة التقرير وقائمة الحماية، وإثبات نسخة احتياطية قابلة للاستعادة للملفات المعتمدة.
3. بإذن منفصل: تطبيق الترحيل الإضافي والدالة والأسرار داخل الخادم؛ مراجعة صلاحيات الرفع ومنع تجاوز الحذف الآمن مع إبقاء الصوت كما هو.
4. تعبئة سجل المراجع ومقارنته بالجرد؛ يبقى التنظيف معطّلًا حتى اكتمال التغطية وحماية التزامن.
5. بإذن منفصل: تجربة صورة واحدة وعنصر تجريبي جديد على المستقل مع Dry Run أولًا، ثم التحقق من نجاح القراءة والحفظ قبل أي تفعيل أوسع.
6. نشر Vercel والتفعيل الإنتاجي لاحقًا فقط بموافقة صريحة. تنظيف الملفات القديمة يُعتمد بقائمة منفصلة؛ لا حذف جماعي تلقائي.

**النتيجة المستهدفة:** الاستبدال والحذف يوفّران مساحة فعلية عندما يثبت عدم الاستخدام، مع حماية الملفات المشتركة والإبقاء على الحالات غير المؤكدة؛ التنفيذ الآن ينتظر موافقتك على الخطة.
