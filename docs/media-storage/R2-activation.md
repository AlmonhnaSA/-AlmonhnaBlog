# التسليم النهائي للصور — إعداد محلي دون تفعيل إنتاجي

## ما تم تجهيزه
الرفع موحّد في `mediaUploads` لجميع الصور (الغلاف، المعرض، المحرر، المنتجات، الخدمات، الحسابات والخطوط). الصور الأصلية الجديدة لا تُضغط أو تُغيّر أبعادها؛ ملفات PDF ومرفقات المتجر تبقى في التخزين الحالي. موفر R2 منفصل للصورة داخل `media-lifecycle`، مع تسجيل الملكية، توقيع PUT لمدة 600 ثانية بمفتاح جديد وشرط عدم الاستبدال، تحقق الحجم والنوع، ثم حفظ المعاملة والقراءة قبل طابور التنظيف. لا مفاتيح في الواجهة.

حارس المراجع يشمل الجداول العامة والنصوص والمعارض حتى عند تعديلها من مسارات قديمة؛ كل الملفات المشتركة والمراجع الغامضة محمية، والتومستون يمنع إرفاق ملف أثناء حذفه. موفر R2 يحذف الصور الجديدة المُدارة فقط، لا النسخ `legacy` ولا الصوتيات. الحذف يبقى `PHYSICAL_DELETE_ENABLED=false`، وSQL والسياسات والدالة لم تُطبّق.

النسخ المحلي يحفظ المسار `legacy/<bucket>/<key>` والبايتات وSHA-256، ويمنع الاستبدال؛ يمكن إعادة نفس الأمر بعد الانقطاع؛ يتأكد من الملفات الموجودة بدل نسخها مجددًا. لا يغيّر روابط قاعدة البيانات ولا يحذف المصدر. إعادة التحقق تقرأ الأصل والنسخة كاملين، لذلك لها تكلفة قراءة متعمدة مرة لكل تشغيل. التقارير ليست دليل حذف.

## الترتيب الخارجي الوحيد
من نسخة GitHub نفسها، على Windows، ثبّت Bun وSupabase CLI، وأنشئ ملفًا سريًا خارج المشروع بصلاحيات المستخدم الحالي فقط، مثل `C:\Private\media.env`. لا ترفعه إلى Git أو ترسله بالمحادثة. القيم المطلوبة:

```text
MEDIA_EXPECTED_PROJECT=<المشروع المستقل الصحيح>
MEDIA_SUPABASE_URL=<عنوان المشروع نفسه>
MEDIA_SERVICE_KEY=<مفتاح قراءة Storage المحلي>
MEDIA_READONLY_DATABASE_URL=<اتصال مباشر بقراءة كاملة>
MEDIA_SOURCE_SCOPE_REVIEWED=true
MEDIA_PROTECTION_FILE=<مسار JSON لقائمة حماية keys>
MEDIA_EXTERNAL_REVIEWED=true
R2_IMAGES_ACCOUNT_ID=<حساب Cloudflare>
R2_IMAGES_ACCESS_KEY_ID=<مفتاح محدود لحاوية الصور فقط>
R2_IMAGES_SECRET_ACCESS_KEY=<السر المحلي>
R2_IMAGES_BUCKET=almonhna-images
R2_IMAGES_PUBLIC_URL=<عنوان HTTPS الخاص بموفر الصور الجديد>
```

لا تجعل علامات المراجعة true قبل مراجعة المصادر والاستخدام الخارجي. المخطط الحقيقي غير متاح هنا؛ ملف preflight يكشف الأعمدة والسياسات والمنح للمراجعة، وليس تصديق توافق تلقائي. لا تستخدم معرف مشروع التطوير بدل المستقل.

1. **فحص فقط، بلا موافقة كتابة:**
   ```powershell
   bun install
   ./scripts/media/windows.ps1 preflight -SecretFile C:\Private\media.env
   ./scripts/media/windows.ps1 inventory -SecretFile C:\Private\media.env
   ./scripts/media/windows.ps1 dry-run -SecretFile C:\Private\media.env
   bun scripts/storage-cleanup.ts media-reports/inventory.json
   ```
   راجع `schema-preflight.json` مقابل prepare/cleanup وسياسات Storage؛ تحقق من الأدوار والمنح وRLS والعلاقات ON DELETE CASCADE والدوال ونطاق الجداول. لا تغيّر صلاحيات لتجاوز فشل. احفظ نسخة احتياطية فعلية للملفات وبيانات الإنتاج.

2. **بعد الموافقة على إنشاء البنية فقط:** سجّل الدخول إلى Cloudflare محليًا؛ راجع حدود الفوترة قبل الإعداد، ثم:
   ```powershell
   ./scripts/media/windows.ps1 setup-images -SecretFile C:\Private\media.env -ApproveExternalChange
   ```
   الأمر ينشئ حاوية صور منفصلة وينشر Worker جديدًا، لا DNS ولا صوتيات. إذا الحاوية موجودة، يتوقف لتراجعها بنفسك؛ لا يُعيد إنشاءها تلقائيًا. ضع عنوان workers.dev الناتج في R2_IMAGES_PUBLIC_URL. النطاق المخصص اختياري ويحتاج موافقة أخرى.
   اضبط CORS لحاوية الصور فقط: AllowedOrigins عناوين Vercel/النطاقات الفعلية المحددة، AllowedMethods PUT/HEAD، AllowedHeaders Content-Type/If-None-Match/Cache-Control، ExposeHeaders ETag؛ لا تستخدم `*`. لا تغيّر CORS الصوتيات. Worker للعرض فقط؛ PUT مباشرة على R2 بتوقيع الخادم.

3. **بعد الموافقة على نسخ الملفات دون حذف الأصل:**
   ```powershell
   ./scripts/media/windows.ps1 copy -SecretFile C:\Private\media.env -ApproveExternalChange
   ./scripts/media/windows.ps1 verify -SecretFile C:\Private\media.env
   ```
   توقّف عند أي فرق حجم أو SHA-256، حدّث الجرد ولا تستبدل النسخة الموجودة. تحقق أيضًا من روابط الصورة عبر Worker على صفحات الاختبار، لا يكفي S3 وحده. لا تُسجل النسخ legacy كقابلة للحذف.

4. **على نسخة مستقلة معزولة أولًا، ثم بإذن تطبيق إنتاج منفصل:** طبّق بالترتيب `docs/media-storage/prepare.sql` ثم `cleanup.sql` ثم `storage-policies.sql` بعد المراجعة (لا تعِد تطبيقها إذا سبقت). انشر دالة الصور على المستقل فقط:
   ```powershell
   supabase functions deploy media-lifecycle --project-ref <المشروع-المستقل> --no-verify-jwt
   supabase secrets set --env-file C:\Private\edge-images.env --project-ref <المشروع-المستقل>
   ```
   الملف الثاني يحتوي R2_IMAGES_* فقط، و`R2_IMAGES_ENABLED=true` و`MEDIA_MUTATIONS_VALIDATED=true` بعد نجاح الاختبارات؛ `MEDIA_ATTACHMENT_MAX_BYTES` بحسب سياسة المتجر القائمة. اعتمادات SUPABASE_* يستخدمها runtime المشروع المستقل. اختبر إدارة/كاتب/حساب ممنوع، رفع/استبدال/حذف مشترك، فشل الطفل، جلستين متزامنتين وقياس أداء الحارس على الحجم الحقيقي. لا تعتمد على اختبارات محلية لإثبات هذا.

5. **النشر اليدوي بعد الاختبار وموافقتك:** المتغيران الاختياريان في Vercel `VITE_IMAGE_BASE_URL` و`VITE_IMAGE_SOURCE_PROJECT` ينقلان عرض روابط Storage العامة القديمة والمحوّلة إلى Worker مع رجوع للأصل عند الفشل. الروابط الموقعة/الخاصة تبقى الأصل؛ لا تحوّلها إلى عامة. الروابط الموجودة خارج الموقع تبقى على المصدر القديم. اختبر الصفحات والمحرر والمعارض والتقديم في الإنتاج قبل أي حذف مصدر.

6. **الحذف موافقة مستقلة:** سجل القديم عبر `media_register_legacy()`، ثم راجع قائمة أصول محددة وأصحابها ومراجعها الثابتة والخارجية والنسخ الاحتياطية. تحديث `deletion_reviewed` و`media_protections` و`media_cleanup_release` ليس تلقائيًا. بعد اختبار مستقل وموافقة إصدار منفصل فقط يغيَّر ثابت الحذف الخادمي؛ لا سر ولا زر يفعله. جدوِل استدعاء cleanup بحساب إدارة آمن لإعادة محاولات الطابور؛ لا تمنح صلاحية للمستخدم العادي. الصور القديمة غير المرتبطة تحتاج مراجعة منفصلة؛ أداة الجرد لا تمنح إيصالات حذف.

## التراجع والكلفة
```powershell
./scripts/media/windows.ps1 rollback -SecretFile C:\Private\media.env
```
يعرض خطوات التراجع ولا يغيّر الخدمات: عطّل الرفع الجديد واحذف متغيرات تحويل العرض في نشر Vercel يدوي جديد، أبقِ المصدر وR2 وWorker (روابط R2 الجديدة المباشرة تحتاجه). لا استبدال ولا حذف ولا إعادة كتابة بيانات حصلت بالنقل. لا يمكن استعادة بايتات حُذفت لاحقًا بمجرد الرجوع بالكود.

Worker يستخدم كاش الحافة على GET؛ المفاتيح الجديدة immutable. لا resize في Worker لأن Image Resizing خدمة منفصلة وقد تكون مدفوعة؛ يُعرض الأصل دون خسارة جودة، وقد يزيد حجم تحميل الصور الجديدة مقارنة بالتحسين السابق. رُجّح حفظ الجودة بدل اختراع ضغط غير معتمد. يُنصح بقياس الأبعاد والحجم بعد النقل قبل طلب تحسين منفصل.

حدود R2 Standard المنشورة: 10 GB-month تخزين، مليون Class A، 10 ملايين Class B مجانًا شهريًا؛ التخزين الزائد $0.015/GB-month وClass A $4.50/مليون وClass B $0.36/مليون، نقل الإنترنت الخارجي مجاني لـR2، وWorker له حدود/تسعير مستقل. تحقق من الأسعار الحالية قبل تفعيل الحساب: https://developers.cloudflare.com/r2/pricing/ و https://developers.cloudflare.com/workers/platform/pricing/ . النسخ يزيد التخزين لأن المصدر يُحتفظ به؛ لا مراقبة أو فواتير فُعّلت هنا. شغّل نسخًا متسلسلًا وافحص usage في Cloudflare بعد العملية بدل إعادة الجرد والنسخ بلا داعٍ.

## حدود التحقق
اختبارات SQL المحلية لا تمثل مخطط الإنتاج أو جلستين حقيقيتين؛ توقيع R2 والرفع وحذف مساحة فعلية وWindows/CORS لم تُختبر على خدمات حقيقية لعدم وجود وصول مستقل مصرح. الكود جاهز للتجربة المعزولة والمراجعة، وليس تفعيل الحذف المباشر. كل تغييرات الإنتاج والنسخ والنشر تحتاج موافقتك.
